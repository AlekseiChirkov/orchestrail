## Goal

## Context
- Dependencies: T-02a (facts), T-02b (projection fields `branch_model`, `phases`, `tdd_order`), T-02c (HC-2 replay results, missed defects, claimed success)
- Constraints: Python 3.11+ standard library, `git` and an already installed `pytest` only, run as `python3 -I`; strict and canonical JSON as defined in the specification; every process launch stays inside `scripts/golden_*.py`; the N > 1 clauses of SA-10/SA-11 are reserved and not implemented; SA-11's step name is today's `pe-execute`; tests extend `tests/golden-runs.py`; the source guard is re-pinned in this subtask; contract: `.ai/specs/012-golden-run-tests.md` REQ-03, REQ-08, REQ-15, REQ-18, REQ-19, REQ-28, REQ-29 (check-relevant rows), REQ-48, REQ-51, DM-3 assertions and TDD evidence table, DM-10 rows 4, 8, 9.
- Reason: semantic assertions with the check outcome form one rule engine over facts with one criteria cluster (assertion results and outcome), testable without golden comparison.

Off-limits: `scripts/validate-contracts.sh`, `scripts/sync.sh`, every file under `rules/` and `workflows/`, any CI file; any paid model run or real `claude` invocation; installing anything at run time; non-English content; planning identifiers (subtask ids, spec numbers, `.ai/` paths, requirement or criterion ids) in product code, comments, test names or documentation — product checks such as SA-10's commit-subject rule match the pattern, they do not name it; deleting, skipping or weakening tests frozen by earlier subtasks; writing under `tests/expected/`; outcome rows that need evaluation records, cancellation or policy stops (T-05, T-06a).
